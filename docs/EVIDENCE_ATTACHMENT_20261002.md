# D2 및 품질 증거 저장소 첨부 기능 — 2026-10-02

## 사용 방법

1. 작성 중인 내용이 있으면 기존 화면에서 임시 저장한 뒤 새로고침한다.
2. D2 화면 상단의 **근거 자료 (Evidence) → 파일 첨부**에서 고객 메일 이미지, Report 또는 측정 파일을 선택한다. 끌어 놓기와 여러 파일 선택도 지원한다.
3. 자료 유형을 선택한다. D2에서 첨부하면 D2에 연결된다. 품질 증거 저장소에서는 D1~D8 중 연결 단계를 직접 선택할 수 있다.
4. 첨부 완료 및 **QMS 원본 보관** 표시를 확인한다. 목록의 **원본 보기 / 다운로드**로 실제 파일을 확인한다.
5. 5W2H·IS/IS NOT·사실 검토를 완료하고 D2 검토 리포트를 연다. 첨부는 승인으로 처리되지 않는다.

## 구현 및 저장

- 허용: PNG/JPG/JPEG/WebP/PDF/XLSX/XLS/CSV/DOCX/EML/TXT. 빈 파일 제외, 파일당 최대 30 MB.
- 새 Case 첨부: 실행 중인 QMS의 SQLite `evidence_metadata` + `evidence_files`에 원본과 SHA-256 보관. 본문을 JSON 업무 상태나 Git에 넣지 않는다.
- 원본·Case 연결·중앙 revision·감사 이력을 같은 트랜잭션으로 저장한다. 저장 충돌/잘못된 파일은 원본과 연결 모두 롤백한다. 여러 파일은 파일별 처리하며 앞서 성공한 파일은 유지한다.
- 로그인, 동일 출처, CSRF, 기존 내부 업무 역할을 확인한다. 원본 요청은 Case+Evidence ID를 확인하며 외주 계정/비로그인 원본 열람은 차단한다.
- D2 검토는 D2에 연결된 실제 보관 원본을 읽을 수 있어야 진행된다. 파일명만 있는 항목/없는 로컬 파일/D4에만 연결된 파일은 대신 사용할 수 없다. D2 AI 입력도 실제 저장 파일을 읽는다.
- 신규 `stageScoped` 자료는 연결 단계의 결재 내용에만 포함하여 D2 첨부가 D1 CFT 결재를 무효화하지 않게 했다. 기존 자료/결재 snapshot 형식은 유지한다. 이미 결재한 연결 단계의 자료가 바뀌면 그 단계 이후의 기존 결재는 감사 이력에 보존하고 재검토 상태로 전환한다.
- D2 입력을 첨부 전에 저장하며 첨부 중 폼의 편집을 잠근다. 저장 성공 전에 첨부 완료라고 표시하지 않는다. 요청 결과를 알 수 없거나 로컬 저장이 실패하면 새로고침하여 중앙 목록을 먼저 확인하도록 안내한다.
- 파일 목록은 HTML을 이스케이프한다. 이미지/PDF/작은 TXT·CSV·EML은 실제 원본 미리보기, 다른 문서는 다운로드하여 확인한다.

## 검증

- Python 회귀 41건 통과: 기존 QMS/Agent/서버 동작 및 신규 원본 HTTP 5건 포함. 신규 테스트는 별도 임시 DB 사용.
- 실제 Edge: 파일 선택 입력을 통해 시험용 eMMC 메일 이미지 원본 업로드, SHA-256 일치, 입력 내용 유지, 재로드 유지, 별도 브라우저 저장소/다른 내부 담당자 계정 원본 열람, 실패 시 가짜 목록 항목 없음, 미리보기·다운로드 바이트 일치, D2 검토 리포트 진입 및 자동 승인 없음, 후속 실제 첨부 후 D1 서명 유지, D2 누락/잘못된 단계 검증 등 기능 21건 통과.
- 다크/라이트 × 1280/390px × D2/증거 저장소/이미지 원본 팝업 12화면: 대비/잘림/겹침/본문 넘침 실패 0, 런타임 예외 0.
- 실제 결재 기록과 외부 AI 호출 없이 검토 진입까지만 확인했다. 테스트의 이전 D1 서명은 폐기용 DB의 화면 fixture이며 운영에 기록하지 않았다.
- 결과: `output/theme_layout_20261002/evidence_verified.json`, 해당 스크린샷/원본 다운로드 파일, `output/evidence_regression_suite.log`.
- 재실행: `python -m unittest discover -s tests -p test_evidence_http.py -v`; 브라우저 검증은 `QMS_AUDIT_EVIDENCE_ONLY=1`, `QMS_AUDIT_LABEL=evidence_verified`를 설정하고 `node tests/theme_layout_audit.cjs`. 기존 시험 메일 PNG fixture가 output/imagegen 아래 있어야 한다. 독립 실행 Python 테스트도 시작 전에 임시 QMS_DATABASE_PATH를 설정하면 최초 모듈 import의 운영 DB 접근을 피할 수 있다.

## 운영 적용 및 남은 범위

- localhost 8765의 해당 프로젝트 서버를 확인한 뒤 새 원본 API를 적용하기 위해 재시작했다. 재시작 직전 업무 상태 revision 329와 stateHash가 재시작 후 동일한 것을 확인했다. 실제 등록된 Case/접수 각 1건은 보존하고 시험 자료를 운영에 등록하지 않았다.
- PID 33720. 정적 파일 제공 내용과 인증된 새 API 활성화 확인. 변경 JS/CSS 캐시는 `20261002_evidence_v1`.
- 변경 전 소스: `backups/d2_evidence_20261002_102356`; 재시작 전 업무 상태만 따로 보존한 사본: `backups/evidence_runtime_20261002_103414`를 포함한 evidence_runtime_* 폴더(인증/세션 제외).
- 저장 장소는 현재 실행하는 로컬 QMS 인스턴스다. GitHub 업로드/다른 PC 서버 연결은 이 수정에 포함되지 않는다. 동일 QMS의 별도 브라우저/담당자 접근은 검증했고 실제 다른 PC 접속은 미검증이다.
- 기존 접수/기존 D4 품질도구의 IndexedDB 원본은 그대로 유지한다. 기존 브라우저에서만 읽히는 파일을 자동으로 중앙 업로드하지 않았다. PCN 파일 저장 구조도 이번 변경 범위 밖이다.
- 의존성 추가 없음. 원본은 Git 제외 대상인 SQLite에 보관하며 자격 증명을 문서에 기록하지 않았다.
