# D5 AI 대책 후보 추천 (2026-10-03)

## 목적

D4에서 사람이 확정한 원인마다 영구 시정조치 후보를 받아, 대책을 처음부터 떠올려야 하는 부담을 줄인다. 대책의 선정·담당·일정·Evidence는 사람이 정한다.

## 동작

1. D5 화면 **AI에게 대책 후보 추천받기**를 누른다. 작성 내용을 먼저 중앙에 저장한다.
2. 서버가 중앙 저장 Case를 확인한다. D4 원인 중 상태가 **Confirmed**이고 원인 문장이 있는 것이 하나도 없으면 409(`ACTION_ADVICE_NO_ROOT_CAUSE`)로 거부하고 AI를 부르지 않는다.
3. 외부 AI(Gemini, 실패하면 Groq)에 보내는 것: 고객사·제품·품번·Lot·불량 현상, D2 문제 정의문, **확정 원인**(문장·입증 Evidence·검증 방법), D4 도구 결과 중 사람이 사실 확인한 것, 이미 등록된 D5 대책 제목, 유사 종결 Case(유사도 0.5 이상, 최대 3건)의 선정 대책. 확정되지 않은 원인과 확인되지 않은 결과는 보내지 않는다.
4. 응답 검증: 확정 원인에 연결된 대책만 남기고, 원인당 최대 3개. 강도·적용 위치·4M·PCN 값이 선택지 밖이면 가장 보수적인 값(강도 "교육·표준", 위치 "미확정", PCN "판단 불가")으로 둔다.
5. 서버가 직접 점검한다(AI 응답의 자기 평가를 쓰지 않음).
   - 확정 원인인데 대책 후보가 없음
   - 한 원인의 후보가 모두 교육·표준 수준 → "이것만으로는 재발할 수 있습니다"
6. 화면: 원인별로 대책 후보, 강도(원인 제거 / 실수 방지 / 검출 강화 / 교육·표준), 원인 제거 방식, 강도 판단 이유, 적용 위치(TechL·WinPAC·CTST·사내)와 변경 4M, 고객 PCN 필요 가능성과 이유, 부작용·위험, 검증 방법, 적용 제약.
7. 후보에 체크하고 **체크한 대책을 목록에 추가**를 누르면 D5 대책 목록에 들어간다. 선정은 "안 됨", 담당자·목표일·비용·Evidence는 빈칸. PCN 필요 가능성이 높은 대책이 있으면 PCN 필요 여부를 직접 판단하라고 알린다(자동으로 바꾸지 않음).

## 지키는 것

- AI는 대책을 선정하지 않고, 담당자·날짜·금액·시료 수·측정값을 쓰지 않도록 지시받는다. 효과를 단정하지 않는다.
- 추천(`actionAdvice`)은 결재 스냅숏에서 제외한다. 서버는 추천을 Case에 쓰지 않는다.
- 감사 로그 `D5_ACTION_ADVICE_GENERATED`.

## 구현

- `action_advisor.py`: 프롬프트, 응답 검증, 서버 점검, `ActionAdvisorMixin`.
- `portal_server.py`: `POST /__api__/qms/ai/d5-action-advice`. D4와 함께 쓰는 `ask_ai_for_advice`(Gemini → Groq, 검증 통과한 첫 응답).
- `js/views/d5_action_advisor.js`, `js/late_stages.js`(D5 화면에 패널), `js/approval.js`(스냅숏 제외).

## 검증

- `tests/test_action_advisor.py` 6건(AI는 모의): 확정 원인만 사용, 원인당 3개 제한, 잘못된 값의 보수적 처리, 약한 대책·누락 원인 점검, 확인 안 된 결과·후보 원인·미선정 과거 대책을 보내지 않음, 확정 원인 없으면 AI 호출 없이 409, 권한, 두 AI 모두 실패 시 502.
- 실제 Gemini로 시험 Case([검증용] 확정 원인 3개: 리플로우 피크 온도 초과 / 출하 테스트에 부팅 확인 없음 / PFMEA·변경 승인 절차 부재) 확인: 약 7초, 원인마다 2개씩 6개 후보. 교육 대책은 "교육·표준"으로, 리플로우 프로파일 변경은 "원인 제거 · PCN 검토 필요"로 분류했다. 4개를 체크해 추가했고 선정 안 됨·빈 담당/목표일/Evidence로 들어간 것을 확인했다.

## 한계

- 강도 분류는 AI 판단이다. 예를 들어 PFMEA 개정을 "실수 방지"로 분류했는데, 사람에 따라 "교육·표준"으로 볼 수 있다. 약한 대책 경고는 이 분류에 의존한다.
- 비용·일정 판단은 하지 않는다.
- 유사 Case 참고는 종결 Case가 쌓여야 의미가 생긴다.
