# 알림 메일 (SMTP)

2026-10-02 사용자 결정으로 SMTP 발송을 구현했다. 범위는 **사내 알림 메일**이다.

## 범위

| 구분 | 상태 |
|---|---|
| 부적합 공유 메일 (D1 팀 확정 시) | 구현. 확정된 팀원에게 접수된 부적합을 공유 |
| SLA 기한 알림 메일 (Case, 검토 대기 접수) | 구현. 주의·임박·초과 세 단계 모두. 초과는 매일 1회 반복 |
| 시험 메일 | 구현. 화면에서 1통 발송 |
| 고객 보고서 송부 | 시스템이 보내지 않는다. 기존대로 외부에서 송부한 뒤 증빙을 기록하며 `dispatch_outbox`는 `PREPARED`·`UNDECIDED`로 남는다 |
| 외주사 통보 메일 | 미구현. 사이트 수신함 공개만 한다 |

## 설정 (`.env`)

메일 설정은 발송할 때마다 `.env`를 다시 읽으므로 서버를 다시 시작하지 않아도 반영된다. `.env`는 Git에 넣지 않는다.

| 키 | 설명 |
|---|---|
| `QMS_MAIL_PROVIDER` | `SMTP`여야 발송한다 |
| `QMS_EXTERNAL_SEND_ENABLED` | `true`여야 발송한다 |
| `QMS_SMTP_HOST`, `QMS_SMTP_PORT` | SMTP 서버 주소와 포트 |
| `QMS_SMTP_SECURITY` | `STARTTLS`(보통 587), `SSL`(보통 465), `NONE` |
| `QMS_SMTP_USER`, `QMS_SMTP_PASSWORD` | 로그인 계정. 계정이 비어 있으면 로그인 없이 보낸다 |
| `QMS_MAIL_FROM` | 보내는 주소. 비우면 로그인 계정을 쓴다 |
| `QMS_MAIL_TEST_MODE` | 기본 `true`. 켜져 있으면 모든 메일이 시험 수신자 한 명에게만 간다 |
| `QMS_MAIL_TEST_RECIPIENT` | 시험 수신자. 기본 `sjkim@ramostek.com` |
| `QMS_MAIL_SLA_LEVELS` | 메일을 보낼 SLA 단계(쉼표 구분). 기본 `L1_ATTENTION,L2_CRITICAL,L3_OVERDUE` |

## 동작

- **시험 모드**: 실제 수신 대상과 관계없이 시험 수신자에게만 보낸다. 제목 앞에 `[QMS 시험]`이 붙고 본문 첫 줄에 원래 대상이 적힌다. 원래 대상은 발송 기록에도 남는다.
- **부적합 공유 메일**: D1에서 사람이 팀 구성을 확정(`cftRecommendation.humanConfirmed`)한 저장이 끝나면 팀원 이메일(`team[].contact`)로 보낸다. 내용은 Case에 기록된 고객사·제품·품번·Lot·불량 현상·발생 위치·수량·접수 시각과 3D/5D/8D 기한 규칙, 팀 명단이다. 같은 팀 구성에는 한 번만 보내고, 확정된 팀의 구성원이 바뀌면 다시 보낸다.
- **SLA 메일**: 주의(L1)·임박(L2)은 알림 기록이 생길 때 한 번 보낸다. 초과(L3)는 생길 때 보내고, 초과 상태가 이어지는 동안 하루(KST 날짜 기준)에 한 번 다시 보낸다. 대상은 Case 팀원이며, 팀이 아직 없는 검토 대기 접수는 그 알림의 역할을 가진 활성 계정이다.
- **기록 중복 방지**: 스케줄러는 1분마다 평가한다. 같은 건의 결과가 직전과 같으면(꺼짐·미설정·수신자 없음) 다시 기록하지 않고, 발송 실패는 1시간에 한 번만 재시도한다.
- **실패 처리**: 발송에 실패해도 SLA 평가는 계속된다. 결과는 `mail_log`에 `SENT`, `FAILED`, `DISABLED`, `NOT_CONFIGURED`, `NO_RECIPIENT`로 남고 감사 로그에도 기록된다.
- 메일은 DB 작업이 끝난 뒤에 보낸다. 메일 서버가 느려도 저장이 막히지 않는다.

## 화면

Agent Operations 상단의 **알림 메일 설정·시험**. 시스템 관리자와 품질 검토자에게만 보인다.

- 현재 설정(서버 주소, 계정, 보내는 주소, 시험 모드 여부)을 보여 준다. 비밀번호는 설정 여부만 표시한다.
- **시험 메일 1통 보내기**로 발송을 확인한다.
- 최근 발송 기록 30건.

## 구현

- `mailer.py`: 설정 읽기, SMTP 발송, `mail_log` 테이블, `MailerMixin`.
- API: `GET /__api__/qms/mail/status`, `POST /__api__/qms/mail/test`.
- `qms_backend.py`의 `evaluate_sla_escalations`가 열려 있는 알림을 `_mail_sla_escalations`에, `save_state`가 저장 전후 상태를 `_mail_team_assignments`에 넘긴다.
- 추가 패키지 없음(표준 라이브러리 `smtplib`).

## 검증

`tests/test_mail.py` 12건. SMTP 접속은 모의 객체로 대체했다: 기본 꺼짐, 시험 모드 수신자 고정, 주의 단계 1회 발송, 설정에서 뺀 단계 미발송, 초과 알림 하루 1회 반복, 같은 결과 중복 기록 없음, D1 팀 확정 시 공유(미확정 미발송·재저장 미발송·팀 변경 시 재발송), 실제 모드 수신자, 발송 실패 기록, 권한.

2026-10-02 사내 메일 서버로 시험 메일 1통을 보냈고 사용자가 수신을 확인했다. 구성은 25번 포트, `QMS_SMTP_SECURITY=NONE`, 로그인 없는 릴레이다. 이 서버는 STARTTLS를 지원하지 않는다.

## 사용자 결정 (2026-10-02)

1. 부적합 접수 후 D1에서 인원이 확정되면 그 인원에게 접수된 부적합을 공유한다.
2. SLA 메일은 주의·임박·초과 모두 보낸다. 초과는 매일 1회 반복한다.
3. 평가 기간에는 모든 메일의 수신인을 sjkim@ramostek.com 한 명으로 둔다(`QMS_MAIL_TEST_MODE=true`). 이후 조직도에 등록된 사람에게 보내도록 전환한다.

## 실제 발송으로 전환할 때

- `.env`의 `QMS_MAIL_TEST_MODE=false`로 바꾸면 Case 팀원(조직도에서 고른 사람)의 이메일로 간다. 사용자가 지시하기 전에는 바꾸지 않는다.
- 전환 전에 조직도 이메일이 실제 주소인지 확인한다. 팀이 없는 검토 대기 접수의 알림은 역할 보유 계정으로 가며, `master@qms.local`처럼 실제 주소가 아닌 계정이 섞여 있다.
- 비밀번호를 쓰게 되면 보관 위치(지금은 `.env`)를 OS 자격 증명 저장소로 옮길지 검토한다.
