# 다크·라이트 모드 및 글자 가독성 수정 — 2026-10-02

## 완료 내용

사용자 요청에 따라 기존 산업용 화면 구성을 유지하면서 공통 테마·글자·좁은 화면 표시를 수정했다. 접수, Case, D1~D8, 3D/5D/8D 보고서, 외주 PCN·조립 이슈, 조직도 및 주요 팝업을 확인했다.

| 대상 | 적용한 수정 |
| --- | --- |
| 다크 모드 | 보조 글자와 빈 상태 문구의 대비를 높이고 상태 색상을 보정 |
| 라이트 모드 | 외주사 메뉴·진행 배지·알림·로그인·CoQ의 옅은 색을 읽을 수 있는 색으로 보정 |
| 글자·긴 내용 | 작은 HTML 글자를 화면에서 최소 12px로 보정, 단계명·요청명·담당자·파일명·문서 제목 줄바꿈 허용 |
| 단계·분석 카드 | 본문 폭에 맞춰 열 수를 조정하고 D4 도구 카드와 미션 단계 설명이 내용에 따라 늘어나도록 조정 |
| 좁은 화면 | 900px 이하에서 메뉴를 접고 펼치도록 제공, 상단 조작 버튼·보고서 Gate 카드를 줄바꿈 배치 |
| 표·도표 | 큰 표는 표 안에서 키보드/마우스로 좌우 스크롤, 분석 그림 비율 유지 및 좁은 화면 재배치 |
| 보고서·뷰어 | 두 모드 모두 흰 보고서 내부의 글자 색을 별도로 지정, 장식 워터마크가 화면 폭을 늘리지 않도록 제한, 긴 문서 제목 표시 |
| SLA 경고 | 지연 경고의 글자까지 흐려지는 투명도 깜빡임을 제거하고 경고 문구를 계속 선명하게 표시 |

표시 보정은 `css/ui_readability.css`와 `js/ui_readability.js`에 분리했다. 동적 화면/팝업 렌더링에도 표 스크롤·작은 글자 보정을 적용한다. SVG 내부 글자는 일괄 확대하지 않아 그림 비율을 보존한다. 인쇄에서는 표 보정 래퍼를 `display:contents`로 처리하고 화면 전용 글자/배치 규칙을 적용하지 않는다. 기존 Agent Operations 실행 단계 겹침 수정은 그대로 포함한다.

## 검증 결과

- 실제 Edge에서 다크/라이트 × 1600/1280/1024/768/390px × 31개 화면·팝업 = 310건.
- 로그인 4건, 실제 인증된 외주사 계정 `thkwon`, `yspark`, `sangwook.ki`, `ojs`의 관제/PCN/조립 이슈 화면 48건을 더해 **총 362건 통과**.
- 전체 확인 뒤 추가한 SLA 표시 보정에 대해 좁은 보고서/뷰어/외주 접수 및 외주사 계정 화면 **62건 추가 통과**.
- 검사 대상으로 삼은 HTML 텍스트 대비 실패·숨김 영역에서의 잘림·다른 텍스트와의 겹침·본문 전체 가로 넘침·런타임 예외 0건.
- 모바일 메뉴 열기/메뉴 선택 후 닫기, 테마 설정 저장, SLA 경고 투명도 고정 확인.
- 3D/5D/8D 보고서의 PDF 렌더링 3건 성공. PDF 전체 페이지의 수작업 인쇄 검수까지 수행했다는 뜻은 아니다.
- 대표 다크/라이트 및 좁은 화면 스크린샷 확인. 단색 배경의 일반 글자는 대비 4.5:1, 큰 글자는 3:1을 검사했다. SVG·장식 워터마크·그라데이션 글자 배경은 자동 대비 판정에서 제외하고 화면 이미지로 보완했다.
- 새 UI/기존 Agent Operations JS 문법 검사 및 Git diff 형식 검사 통과. 패키지 추가 없음.

검증은 임시 SQLite와 별도 브라우저 프로필, 기본 시연 Case/메모리 접수 자료로 수행했다. 운영 DB·접수·승인·외부 AI·이메일을 실행하거나 쓰지 않았다. 정상적인 긴 표의 내부 스크롤 및 입력/선택 필드의 편집 동작은 글자 오류로 처리하지 않는다. 확인한 시연 자료와 화면 폭에서의 표시 검증이며 실제 업무 전체 E2E 결과가 아니다.
