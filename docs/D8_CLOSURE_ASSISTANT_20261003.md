# D8 종결 도우미와 종결 조건 (2026-10-03)

## 종결 조건 — 사용자 결정 2026-10-03

- Case 종결 = **간사 기안 → 리더 승인 → 챔피언 승인**(D8 단계의 8D Report 결재). 챔피언 승인 시 Case 상태가 Closed가 된다(기존 동작 유지).
- **고객 송부와 고객 수락은 종결 조건이 아니다.** 3D/5D/8D 고객 보고서 결재·송부(Report Gate)는 별도 기록으로 남는다.
- 변경: D8 필수 항목에서 "고객 수락"을 뺐다. 필수는 잔여 위험과 종결 근거. 칸 이름을 "고객 요구사항·수락 (해당 시, 종결 조건 아님)", "종결 근거 (8D Report 결재 기준)"로 바꿨고, 기본 종결 점검 4번 항목도 "고객 보고 필요 여부·송부 계획 (종결 조건 아님)"으로 바꿨다. 규칙 초안(stage_drafts)과 Excel 보고서 이름도 맞췄다.

## 도우미 구성

| 부분 | 방식 | 하는 일 |
|---|---|---|
| ① 종결 준비 점검 · 처리 기간 | 규칙·계산 | D1~D7 결재, D6 PASS·봉쇄 결정·전후 비교, D7 완료, 고객 PCN, 교훈, 고객 보고 송부(참고). 접수 → 챔피언 승인까지 3D 24시간·5D 14일·8D 30일 대비 소요 시간. 종결 점검표의 빈 근거 칸을 기록으로 채우기(확인 체크는 사람) |
| ② 전체 일관성 검토 | 외부 AI | D2↔D4, 원인↔대책, 대책↔D6 검증, 수량·Lot·날짜, D7이 시스템원인을 다루는지. 중요/보통/참고로 지적만 하고 승인 여부는 판정하지 않음 |
| ③ 종결 초안 | 외부 AI | 잔여 위험, 고객 종결 요약(한국어, 선택 시 영문), 팀 인정 문구. "칸에 넣기"는 이미 쓴 내용이 있으면 확인 후 교체. 고객 요약은 복사해서 송부 |
| ④ 종결 후 재발 모니터링 | 규칙 + 알림 메일 | 기본 30·60·90일(변경 가능). 기준일은 종결일(종결 전이면 오늘). 기한이 되면 Case 팀에게 알림 메일(평가 기간에는 시험 수신자 한 명). 결과(재발 없음/재발/확인 불가)와 내용을 기록 |

- 모니터링 일정은 Case의 `postClosureMonitoring`에 둔다. D8 단계 데이터가 아니어서 종결 후 만들어도 D8 결재가 다시 열리지 않는다.
- AI 결과(`consistencyReview`, `closureDraft`)는 결재 스냅숏에서 제외한다.
- 알림 메일은 `mailer._mail_monitoring_due`가 SLA 평가 때 함께 확인한다(kind `MONITOR`, 항목당 한 번).

## API

`POST /__api__/qms/d8/readiness`, `/d8/monitoring-plan` {caseId, days}, `/ai/d8-review`, `/ai/d8-draft` {caseId, english}. 사내 로그인 필요. 감사 로그 `D8_CONSISTENCY_REVIEWED`, `D8_CLOSURE_DRAFTED`.

## 검증

- `tests/test_closure_assistant.py` 9건(AI·SMTP 모의): 준비 점검(통과·차단·고객 보고는 참고), 처리 기간(기한 내·초과), 점검표 근거, 검토 결과 검증, 초안·영문 선택, 모니터링 기준일, API·권한, 기한 도래 모니터링 메일 한 번(시험 수신자).
- 시험용 DB·실제 Gemini로 화면 확인: 준비 점검 전부 통과(고객 보고 송부 없음은 참고), 점검표 근거 채우기, 초안(잔여 위험·한국어·영문 요약·팀 인정). **고객 수락 칸을 비운 채 간사→리더→챔피언 결재로 Closed** 확인(고객 8D 보고서 Gate는 대기 그대로). 종결 후 모니터링 일정을 만들어도 D8 결재 유지.
- 첫 일관성 검토에서 AI가 "적용 Lot이 불량 Lot과 다름", "적용일이 시험일보다 앞섬"을 모순으로 지적했다. 둘 다 정상이어서 검토 지시에 "정상인 것" 목록을 넣었고, 다시 검토하니 지적 없음으로 나왔다.

## 한계

- 고객 보고 문안은 Case 기록만으로 쓰므로 고객별 양식(예: 고객 지정 8D 서식)은 반영하지 않는다.
- 영문 요약의 고객사 이름은 기록된 한글 이름을 그대로 쓸 수 있다(사람이 고쳐야 함).
- 모니터링은 알림과 기록까지다. 재발 클레임을 자동으로 찾지는 않는다.
