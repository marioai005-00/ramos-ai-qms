## 1. D4~D8 근거 기반 초안

### 사용

- D4 화면: "기록된 사실로 분석 목적 초안 만들기" 카드의 **근거 기반 초안 생성**.
- D5~D8 화면: 상단의 **근거 기반 초안 생성**. 기존 외부 AI 버튼은 **외부 AI 초안**으로 남아 있으며 AI 공급자 설정이 있어야 동작한다.
- 초안 패널은 Case에 기록된 사실, 추론(확정 아님), 누락·확인 필요, 제안, 참고(유사 종결 Case), 권고를 따로 보여 준다.
- **제안을 미확인 상태로 추가**를 누르면 제안 행이 미선정·Pending·Open 상태로 들어간다. 담당자가 이미 쓴 내용은 덮어쓰지 않는다.

### 초안이 읽는 것

| 자료 | 쓰임 |
|---|---|
| 중앙에 저장된 Case | 접수 사실, 결재 완료 단계, Evidence 목록 |
| D2 IS / IS NOT 중 사실 확인된 행 | D4 변경점 분석 목적, 추론 |
| D4 확정 원인(Confirmed) | D5 대책 틀, D7 동일 위험 평가 문구 |
| D5 선정 대책 | D6 검증 시험 틀, D7 표준 개정·수평전개 틀 |
| 이 Case에 연결된 외주 접수 | 사실 목록, D4 변경점, D5 후보(승인된 PCN) |
| 유사도 0.5 이상 종결 Case | 참고 목록, D5 후보 |

### 초안이 만들지 않는 것

원인 문장, 측정값, 표본 수·불량 수, 판정, 완료 상태, 시험일, 문서 번호·Revision, Evidence 칸, 승인. D8은 종결 점검 칸을 채우지 않고 누락 항목만 알려 준다.

D2에서 사실 확인되지 않은 차이점은 초안 근거로 쓰지 않는다. D4 원인이 확정되지 않았으면 그 원인의 D5 대책은 제안하지 않고 누락으로 표시한다.

### 구현

- `stage_drafts.py`: 규칙 기반 생성. 외부 AI를 호출하지 않아 `.env` 없이 동작한다. 엔진 표기 `server-evidence-rules-v1`.
- `POST /__api__/qms/ai/stage-draft` `{caseId, stage}`. 사내 작성 권한 필요, 외주 계정 차단. 생성 사실을 감사 로그에 남긴다.
- 브라우저는 요청 전에 편집 내용을 중앙에 저장한다. 초안은 저장된 Case를 기준으로 만든다.

## 2. 외주 접수를 8D Case로 가져오기

### 이전 상태

`js/views/supplier_bridge.js`의 D3·D4·D5 연계는 시연용 고정값이었다. 연결되지 않은 접수도 아무 Issue·PCN이나 끌어왔고, 격리 4,800ea·불량 864ea·"무라타 X7R"·`ECN-260901-01`·"LGE 승인 완료"를 Case에 써넣으며 조치를 `Completed`, 대책을 선정으로 표시했다.

### 지금

외주 접수 상세에서 **현재 선택한 8D Case에 연결**을 누른 접수만 그 Case 화면에 나타난다.

| 단계 | 가져오는 것 | 들어가는 상태 |
|---|---|---|
| D3 | 외주사가 입력한 투입·격리·불량 수량과 LOT, 초동 조치 문구 | 재고 흐름 [1. 원자재/협력사] 행 `미확인`, 봉쇄조치 `Open`, 담당자·기한·결과 빈칸 |
| D4 | 외주사가 제출한 원본 파일 | Case Evidence(D4 연결), 출처 메모 "외주 접수 … 제출 원본", 원본 바이트와 SHA-256 보관 |
| D5 | 외주 PCN의 제목·설명·변경 전후 | 대책 후보 `미선정`, 원인 구분·담당자·목표일·Evidence 빈칸 |

- 외주사가 입력하지 않은 수량은 가져오지 않고 기존 값을 둔다.
- ECN 번호, PCN 필요 여부, 고객 승인 상태는 가져오지 않는다.
- 가져오면 해당 단계 결재 상태가 Draft로 돌아간다.
- D4 원본 복사는 기존 Evidence 업로드 API를 그대로 쓰므로 연결 단계 이후의 기존 결재가 재검토 상태가 된다.

## 5. Excel 보고서

8D 리포트 화면의 **Excel 내려받기**. 현재 선택한 Gate(3D/5D/8D) 범위를 `.xlsx`로 받는다.

- 시트: `8D Report`(머리 정보 + 단계별 표), `Evidence`(파일·SHA-256·등록자), `결재 이력`(단계 서명과 보고서 결재, 중앙 기록 번호).
- 3D는 D1~D3, 5D는 D1~D5, 8D는 D1~D8을 담는다.
- 보고서 상태를 첫 줄에 표기한다: `DRAFT · 보고서 결재 전` / `내부 결재 완료 · 송부 전` / `공식 송부 기록 완료`.
- 단계마다 결재 상태를 표기한다. 중앙 결재 기록이 없으면 "미결재 · 작성 중인 초안입니다".
- 빈 칸은 빈 칸으로 둔다.

`report_export.py`는 표준 라이브러리(zipfile)만으로 xlsx를 만든다. 의존성을 추가하지 않았다. `GET /__api__/qms/cases/{id}/report.xlsx?gate=gate8D`. 내려받기는 감사 로그에 남는다.

고객사 지정 양식은 적용하지 않았다. `templates/` 폴더가 비어 있어 기준으로 삼을 양식이 없었다. 고객 양식 파일이 생기면 `build_report_workbook`에 양식별 배치를 추가하면 된다.

## 7. 남은 문제

- 초안은 규칙 기반이라 문장이 정형적이다. 실제 원인 가설을 제시하려면 첨부 원본의 내용을 읽는 단계가 필요하고, 이는 외부 AI 설정 또는 문서 파서 연결이 전제다.
- 외주 접수를 Case에 연결하면 접수 상태가 `8D_Escalated`로 바뀌어 기존 심의 판정 표시를 덮는다.
- D3로 가져온 값을 다시 가져오면 담당자가 고친 수량이 외주사 보고값으로 되돌아간다. 버튼 문구로만 알린다.
- 현황판은 접수가 많아지면 전 건을 읽어 집계한다. 기간 필터가 없다.
