외주 메뉴와 유형 버튼을 모두 분리했다. 외주 PCN/Issue를 전환해도 각각의 양식 입력과 대조표를 보존하며, 기존 첨부 후보의 유형별 보관을 유지한다. 신규 내부 양식의 텍스트 초안은 같은 화면 세션에서 메뉴 이동 시 유지된다. 등록하지 않은 초안은 브라우저 새로고침 전 저장해야 한다.

## 내부 등록과 관리 방법

1. 사내 계정으로 로그인한 뒤 내부 Issue·부적합 또는 내부 PCN 메뉴를 연다.
2. `신규 등록`에서 확인된 정보를 입력한다. 고객 필드는 요구하지 않으며 제품·품번·Lot은 필요할 때 입력한다. 수량 미확인은 빈칸으로 보존하며 0과 구분한다.
3. 사진·PDF·Excel·CSV·DOCX·메일·텍스트 원본을 첨부할 수 있다. 한 요청에 최대 10개, 합계 30 MB이다. 기록·파일·등록 이력은 같은 트랜잭션으로 저장되며 파일 바이트와 SHA-256을 보존한다.
4. 목록에서 제목·품번·Lot·담당자를 검색하고 상태로 필터링한다. 상세 화면에서 원본 다운로드, 담당자·기한 변경, 추가 Evidence, 조치·검토 의견, 기존 8D Case 참조 연결을 관리한다.
5. 접수 또는 반려 상태에서는 기본 정보를 수정할 수 있다. 검토가 시작된 뒤에는 조치/검토 의견에 보완 내용을 기록한다.

생산 Site는 사용자가 지정한 `TechL Vina`, `Winpac`, `SSPC`, `Ramos 3Camp`만 선택할 수 있다. 외주사 마스터 TechL/WinPAC/SSPC/CTST 및 담당자와 계정, 품목·Lot, eMMC 고객 대응 이하영 Pro 규칙은 보존한다.

## 실제 사람의 상태 변경

- 내부 Issue: 접수 → 검토 중 → 조치 중 → 종결. 검토 단계의 반려·반려 후 재접수·종결 후 재검토 경로도 제공한다.
- 내부 PCN: 접수 → 검토 중 → 승인 → 적용 완료. 반려 후 재접수할 수 있다.
- 상태 변경은 서버의 `quality_reviewer` 또는 `system_admin` 권한으로 수행한다. 등록자와 각 검토자는 서버 로그인 계정에서 기록하며 클라이언트가 보낸 이름·승인 상태를 등록 시 신뢰하지 않는다.
- 승인·종결·적용 완료에는 검증 결과와 원본 Evidence가 필요하다. PCN 승인에는 적용 담당자, 적용 완료에는 실제 적용일을 추가로 요구한다.
- 승인된 PCN 및 종결된 Issue의 기존 검증 결과는 일반 관리 저장으로 변경할 수 없다. 추가 의견과 원본은 이력으로 남길 수 있다.
- 내부 PCN 승인은 고객 승인이나 8D 승인으로 간주하지 않는다. 고객 통보 필요 구분은 검토 자료이며 이메일을 보내지 않는다.
- 기존 Case 연결은 참조 관계를 기록한다. 신규 8D 자동 발행·단계 승인·자동 종결을 수행하지 않는다.

## 접근 및 데이터 보존

내부 기록은 기존 고객 Case/접수 JSON과 분리된 `internal_quality_records` 테이블, 첨부는 `internal_quality_files`에 보관한다. 모든 조회·등록·변경·다운로드 API는 서버 인증을 요구하고, 변경에는 CSRF 검증을 적용한다. 외주 계정 4개 모두 내부 목록·상세·등록·원본 접근을 차단한다. 레코드 revision으로 동시 수정 충돌을 차단하고 실패한 상태 변경이나 첨부는 함께 롤백한다. 변경 전후 해시와 로그인 계정을 기존 감사 로그에 기록한다.

외주 기록과 첨부는 이번에 중앙 저장으로 이관하지 않았다. 기존 외주 목록은 해당 브라우저에 보관되고 기존 첨부 경로도 파일 정보 보관 구조이다. 다른 PC/브라우저 간 공유 저장과 외주 원본 저장은 별도 연동이 필요하다. 화면과 접수 완료 문구에 이 저장 범위를 표시한다. 새 내부 기능은 현재 실행 중인 로컬 서버의 저장 기능이며 GitHub 자동 업로드 기능은 아니다.

## 검증 및 적용

- Python 전체 서버 검사 52개 통과: 기존 45개 및 추가 내부 HTTP 검사 7개. 테스트 DB와 모의 AI만 사용했다.
- 실제 Edge 기능 확인 39개 및 화면 조건 96개 통과: 두 테마 × 1280/1024/768/390px, 내부 두 유형 목록/등록/상세와 외주 두 유형 목록/등록, 외주사 4개 계정의 메뉴 클릭·권한 차단. 기능에는 원본 바이트 일치, 등록·수정·담당자 변경, 검증 없는 종결 거절, 새로고침 유지, 초안 분리 및 HTML 이스케이프가 포함된다.
- HTML 텍스트 대비·잘림·겹침·가로 넘침 자동 검사를 사용했다. SVG/그라데이션 및 실측 결과의 사실 진위는 자동 검증 범위가 아니다. 초기 PNG 캡처 일부가 Edge 디버거에서 시간 초과하거나 빈 이미지를 반환해 최종 기능/가독성 검사에서는 PNG 캡처를 분리했다. 초기 캡처는 최종 통과 증거로 사용하지 않는다.
- JS/Python 문법과 git diff --check 확인. 신규 의존성·외부 AI·이메일·운영 테스트 접수·운영 결재 없음.
