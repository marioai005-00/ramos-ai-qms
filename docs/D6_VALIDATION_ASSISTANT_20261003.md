# D6 대책 효과 검증 도우미 (2026-10-03)

D6 화면 위쪽 "대책 효과 검증 도우미". 다섯 부분으로 나뉜다. 숫자는 통계 공식이나 사람이 올린 성적서에서만 나오고, 시험 판정과 봉쇄 해제 결정은 사람이 한다.

| 부분 | 방식 | 하는 일 |
|---|---|---|
| ① 필요한 시료 수 계산 | 통계 공식 | 목표 불량률·신뢰도·허용 불량 수로 시료 수 계산. 기본값은 Case의 원래 불량률 |
| ② AI 시험 계획 추천 | 외부 AI + 공식 | D5 선정 대책마다 시험 방법·조건·합격 기준·비교 대상 제안. 시료 수는 공식으로 계산해 붙임 |
| ③ 성적서 읽기 | 외부 AI + 규칙 | 등록한 성적서 양식 기준으로 값을 읽고 찾은 위치를 함께 표시. PASS/FAIL 제안은 읽은 숫자로 규칙 계산 |
| ④ 개선 전·후 비교 | 통계 공식 | 적용 전 불량률(또는 입력 기준)과 적용 후 시험 결과 비교 |
| ⑤ 적용·봉쇄 해제 점검 | 규칙 | 시험 누락, 시료 부족, 적용일 전 시험, 고객 PCN 미승인, 조건 미충족 해제를 차단·경고 |

## ① 시료 수 (`validation_stats.py`)

- 불량 0개 허용: n = ln(1−신뢰도) / ln(1−목표 불량률). 예: 3,000 PPM, 90% → 767개.
- 불량 c개 허용: 이항분포에서 P(불량 ≤ c) ≤ 1−신뢰도인 가장 작은 n.
- 검출 시험(유출 대책): 불량 시료를 넣어 모두 걸러야 하는 수. 놓칠 확률 5% 미만·90% → 45개.

## ② 시험 계획

- D5에서 **선정된** 대책이 없으면 AI를 부르지 않는다(409 `VALIDATION_PLAN_NO_ACTION`).
- AI에 보내는 것: 제품·불량 현상·Lot·원래 수량, 확정 원인과 재현·검증 방법, 선정 대책과 D5 사전 검증 방법.
- 방법은 재현 조건 시험(발생 원인), 불량 시료 투입 검출 시험(유출 원인), 문서·체계 확인(시스템 원인), 양산 모니터링 중 하나.
- 체크한 계획만 검증 시험 목록에 '대기'로 추가한다. 시료 수·불량 수·판정·담당·시험일은 빈칸이고, 계획 시료 수(`plannedSampleSize`)와 허용 불량 수(`allowedFailures`, 기본 0)를 행에 함께 둔다.

## ③ 성적서 양식과 읽기

- **양식 등록·관리**: 양식 이름, 발행처, 설명, 항목과 "찾는 위치 안내". 시료 수와 불량 수는 필수 항목이다. 양식은 중앙 상태(`reportTemplates`)에 저장되어 모든 사용자가 같이 쓴다.
- **읽기**: 시험 행·양식·파일을 고른다. 파일은 먼저 D6 근거 자료(측정·검사 자료)로 보관한 뒤 AI에 보낸다.
  - PDF·이미지(PNG/JPG/WEBP): Gemini가 파일을 직접 읽는다.
  - Excel(xlsx)·CSV·TXT: 서버가 글자로 바꿔 보낸다(Gemini → Groq).
  - PPT·Word 성적서는 아직 읽지 않는다.
- AI는 양식 항목의 값을 그대로 옮기고 찾은 위치를 적는다. 계산·추정은 하지 않도록 지시한다.
- 서버 규칙: 숫자로 읽히지 않는 값, 불량 수 > 시료 수, 계획보다 적은 시료, 대책 적용일보다 앞선 시험일, 적용 Lot과 다른 시험 Lot, AI가 다른 시험으로 판단한 경우를 표시한다.
- 판정 제안: 불량 수 > 허용 → FAIL, 시료 부족이거나 숫자를 못 찾으면 판단 불가, 그 외 PASS. **판정은 "이 값으로 시험 행 채우기" 후 사람이 직접 고른다.** 채우기는 시료 수·불량 수·시험일·Evidence(파일명)만 옮긴다.

## ④ 전·후 비교

- 판정: 적용 후 불량률의 신뢰 상한(Clopper-Pearson)이 기준(기본: 적용 전 불량률)보다 낮으면 "개선 확인", 실제 불량률은 낮지만 상한이 기준을 넘으면 "판단 불가 — 시료 부족", 낮지 않으면 "개선되지 않음".
- 보조: 적용 전·후 자료끼리의 Fisher 정확 검정 유의확률도 보여 준다. 적용 전 불량 건수가 적으면 이 값이 커서 "우연일 가능성이 남음"으로 표시된다.
- "비교 결과 기록"은 개선 전·후 칸이 비어 있을 때만 채우고 계산 결과를 `beforeAfter.statistics`에 남긴다. 비교 근거(Evidence)는 사람이 쓴다.

## ⑤ 점검 (`validation_advisor.d6_checks`)

- 차단: 선정 대책에 시험 없음, FAIL 시험, 고객 PCN 필요인데 승인 확인 전 적용 기록, 모든 시험이 PASS가 아닌데 봉쇄 해제 선택, 적용 Lot 없이 해제 선택.
- 확인: 시험이 아직 PASS 아님, 계획보다 적은 시료로 PASS, 불량이 있는데 PASS, 적용일보다 앞선 시험일, 연결된 승인 외주 PCN 없음, 전·후 비교가 개선 확인이 아님.
- 기존 D6 승인 조건(lateStageReviewError)은 바꾸지 않았다. 점검 결과는 안내이며 승인을 막지는 않는다.

## API

- `POST /__api__/qms/ai/d6-test-plan` {caseId}
- `POST /__api__/qms/ai/d6-read-report` {caseId, testId, template, file:{name, dataUrl}}
- `POST /__api__/qms/d6/statistics` {kind: sampleSize | compare, …}
- `POST /__api__/qms/d6/checks` {caseId}
- 모두 사내 로그인 필요. 감사 로그 `D6_TEST_PLAN_GENERATED`, `D6_REPORT_READ`.

## 검증

- `tests/test_validation_assistant.py` 13건(AI 모의): 시료 수 공식, 비교 판정 세 가지, 계획의 선정 대책 제한과 계산 시료 수, 성적서 값 규칙(적용일·Lot·시료 부족·FAIL·숫자 아님), 양식 필수 항목, 파일 형식별 변환(CSV cp949, xlsx, PDF), 점검(누락·PCN·해제), API 권한과 응답.
- 시험용 DB·실제 Gemini로 화면 확인: D5 선정 대책 4개에 시험 계획 4개(재현 767개, 검출 45개, 문서 확인 2개). [검증용] PDF 성적서(800 ea / 0 ea)를 양식 기준으로 6개 항목 모두 위치와 함께 읽었고 판정 제안 PASS, 시험명이 계획과 다르다는 점을 표시. 전·후 비교 3/1000 → 0/800 "개선 확인"(상한 2,874 PPM)과 보조 유의확률 0.171. 시험 3개가 대기인 상태에서 봉쇄 해제를 고르면 차단으로 표시.
- 처음에는 성적서 양식이 서버에 저장되지 않아(중앙 저장 항목이 Case·접수뿐) 새로 고침 후 사라졌다. `reportTemplates`를 중앙 저장 항목에 추가했고, 브라우저 저장소를 지운 뒤에도 서버에서 다시 불러오는 것을 확인했다.

## 한계

- 성적서 양식이 아직 정해지지 않았다. 실제 성적서를 받으면 양식을 등록하고 읽기 결과를 확인해야 한다.
- 스캔 품질이 낮은 PDF·이미지는 잘못 읽을 수 있다. 화면의 "찾은 위치"로 원본과 대조해야 한다.
- 한 성적서에 시험이 여러 개 있으면 값 하나를 고르지 못할 수 있다(이때 AI는 비워 두도록 지시받는다).
