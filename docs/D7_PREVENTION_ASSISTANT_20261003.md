# D7 재발방지·수평전개 도우미 (2026-10-03)

D7 화면 위쪽 "재발방지·수평전개 도우미". AI는 제안만 하고, 문서 개정·문서번호·PFMEA 점수·수평전개 확정은 사람이 한다.

| 부분 | 방식 | 하는 일 |
|---|---|---|
| ① 개정할 문서 · PFMEA 초안 · 전파 대상 | 외부 AI | 선정 대책마다 개정할 문서와 바꿀 내용, 확정 원인마다 PFMEA 행(공정·고장모드·영향·원인·예방·검출), 알릴 대상 |
| ② 수평전개 | 기록 + 외부 AI | 기록된 후보마다 동일 위험 있음/낮음/판단 불가와 이유·전개 조치 |
| ③ 교훈 | 외부 AI 요약 + 사람 수정 | 현상·원인·대책·효과·교훈·핵심어. 저장하면 다음 Case의 D5 대책 추천에 유사 사례로 들어감 |
| ④ 빠진 곳 점검 | 규칙 | 대책별 개정 누락, 시스템원인의 PFMEA·Control Plan 누락, 완료 근거·해당 없음 근거, 적용 외주사 수평전개, 교훈 기록 |

## ① 개정·PFMEA·전파

- D5 선정 대책이 없으면 AI를 부르지 않는다(409 `PREVENTION_NO_ACTION`).
- 문서 종류: PFMEA, Control Plan, 작업표준서, 검사기준서, 변경관리 절차, 외주사 관리 기준, 설계 가이드, 교육 자료, 기타.
- 반영하면 개정 목록에 '진행 중'으로 들어가고 문서번호·Revision·담당·목표일·Evidence는 빈칸. PFMEA 행은 `d7.pfmeaDraft`에 들어가며 심각도·발생도·검출도는 "미평가". 전파 대상은 `d7.notifyPlan`.
- 전파 대상은 Case 팀원의 부서와 공식 외주사 3곳 중에서만 고르게 하고, 그 밖의 이름은 버린다.

## ② 수평전개와 제품 목록

- 후보는 기록에서만 만든다(최대 40개): **제품 목록**(화면에서 등록, 중앙 상태 `productCatalog`), 다른 Case의 제품, 외주 조립 불량 기록의 제품, 외주사 3곳의 "다른 제품·라인".
- AI는 후보 목록에서만 판단하며 목록 밖 key는 버린다. 판단 순서는 있음 → 판단 불가 → 낮음.
- 체크한 후보만 수평전개 목록에 '진행 중'으로 들어간다. 해당 없음 판정과 근거, 담당, 실행 근거는 사람이 쓴다.
- **제품 목록 관리**: 제품명, 제품군, 패키지, 외주사, 생산 Site, 거치는 공정, 고객사. 실제 라인업을 등록해야 수평전개가 의미 있다.

## ③ 교훈

- 확정 원인과 선정 대책이 있어야 요청할 수 있다(409 `LESSONS_NOT_READY`).
- AI 요약을 화면에서 고친 뒤 "교훈 저장"을 눌러야 `d7.lessonsLearned`에 남는다.
- 종결된 Case의 교훈은 `similar_cases` 결과에 함께 실리고, D5 대책 추천 프롬프트의 "유사 종결 Case"에 교훈 문장이 들어간다.

## ④ 점검 (`prevention_advisor.d7_checks`)

- 차단: 선정 대책 없음, 대책에 연결된 개정 없음, 완료인데 개정 Evidence 없음, 수평전개 기록 없음, 해당 없음·완료인데 근거 없음.
- 확인: 시스템원인 대책에 PFMEA·Control Plan 개정 없음, 완료인데 문서번호·Revision 없음, D6 적용 장소의 외주사에 대한 수평전개 없음, 교훈 미기록.
- 기존 D7 승인 조건은 그대로다(개정·수평전개 상태가 완료/해당 없음이어야 승인).

## API

`POST /__api__/qms/ai/d7-system-advice`, `/ai/d7-deployment-advice`, `/ai/d7-lessons`, `/d7/checks` — 모두 {caseId}, 사내 로그인 필요. 감사 로그 `D7_SYSTEM_ADVICE_GENERATED`, `D7_DEPLOYMENT_ADVICE_GENERATED`, `D7_LESSONS_GENERATED`.

## 검증

- `tests/test_prevention_assistant.py` 6건(AI 모의): 선정 대책·확정 원인·허용 대상만 남김, PFMEA 점수 미포함, 후보를 기록에서만 만들고 지어낸 후보 제거, 교훈 필수 항목, 점검 차단·확인·통과, API와 409·403.
- 시험용 DB·실제 Gemini로 화면 확인: [검증용] 제품 3개 등록 → 개정 문서 4개(작업표준서·검사기준서·PFMEA·변경관리 절차), PFMEA 3행, 전파 3곳(TechL·CTST·전략소싱팀). 수평전개 후보 6개 중 TechL 리플로우 공정 제품·라인과 CTST는 "있음", WinPAC 쪽은 "낮음"으로 이유와 함께 판단. 교훈 요약 저장 후 점검 "차단 항목 없음".
- 첫 시험에서 AI가 "SMT"를 "에스엠티"로 바꿔 썼다. "영문 코드 금지" 지시 때문이어서, 네 조언 모듈 모두 "시스템 코드값은 쓰지 않되 SMT·BGA·PFMEA 같은 업계 약어는 그대로"로 고쳤다.

## 한계

- 제품 목록이 비어 있으면 수평전개 후보는 다른 Case 제품과 외주사 3곳뿐이다.
- 사내 문서 목록이 없어 문서번호는 추천하지 않는다.
- 전파 대상에 실제 메일을 보내지는 않는다(목록만 남김).
