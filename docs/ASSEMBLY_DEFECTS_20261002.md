# 제품별 외주 조립 불량 관리 — 2026-10-02

메뉴: **외주 품질 관리 → 제품별 조립 불량 관리**. 사내 계정만 사용한다.

## 무엇을 하는 곳인가

외주 조립에서 발생한 불량을 한 건씩 등록하고, 품목코드별로 모아서 본다. 외주사가 직접 제출하는 Issue 접수나 우리가 외주사에 보내는 부적합 통보와는 별개의 사내 기록이다.

## 등록 항목

| 항목 | 필수 | 비고 |
|---|---|---|
| 외주사 | 예 | 공식 외주사 중 선택 |
| 품목코드 (P/N) | 예 | 제품별 집계의 기준 |
| 품명, Lot No., 조립 공정 | 아니오 | |
| 발생일 | 예 | |
| 불량 유형 | 예 | 자유 입력. 같은 문구로 적어야 같은 유형으로 집계된다 |
| 투입 수량 | 아니오 | 모르면 비워 둔다 |
| 불량 수량 | 예 | 투입 수량보다 클 수 없다 |
| 불량 내용, 외주사 조치·봉쇄 내용, 사내 담당자 | 아니오 | |
| 외주 접수 연결, 8D Case 연결 | 아니오 | 실제 존재하는 기록만. 참조만 남긴다 |
| 사진·성적서 원본 | 아니오 | 최대 10개, 합계 30 MB. SHA-256과 함께 보관 |

## 제품별 집계

품목코드마다 기록 수, 미종결 수, 불량 수량 합계, 불량률, 외주사별 불량 수량, 불량 유형별 불량 수량, 최근 발생일을 보여 준다. "이 제품만"을 누르면 아래 기록 목록이 그 제품으로 좁혀진다.

- 불량률은 투입 수량이 입력된 기록의 불량 수량 ÷ 투입 수량이다. 투입 수량이 없는 기록은 불량 수량 합계에는 들어가지만 불량률에서는 빠진다.
- 투입 수량이 입력된 기록이 하나도 없으면 "기록 없음"으로 표시한다.

## 상태와 권한

접수 → 조치 중 → 종결. 조치 중에서 접수로 되돌리거나 종결 후 조치 중으로 재검토할 수 있다.

- 등록·수정·조치 내용 기록: 사내 작성 권한.
- 종결과 종결 건 재검토: 품질 검토 권한(`quality_reviewer`, `system_admin`). 종결에는 조치 결과가 필요하고 종결한 계정이 기록된다.
- 등록할 때 상태나 조치 결과를 지정할 수 없다. 항상 접수 상태로 시작한다.
- 종결된 기록은 재검토를 시작해야 수정할 수 있다.
- 외주 계정은 조회·등록 모두 차단된다.

## 구현

- `assembly_defects.py`: `assembly_defect_records`, `assembly_defect_files` 테이블. 로그인·CSRF·역할 검사, 레코드 revision 충돌 차단, 감사 로그.
- API: `GET/POST /__api__/qms/assembly-defects`, `POST /__api__/qms/assembly-defects/{id}`, `GET .../{id}/files/{fileId}`.
- 화면: `js/views/assembly_defects.js`. 집계는 서버가 계산해서 내려 준다.

- 실제 브라우저(임시 DB): 2건 등록, 제품별 집계 표시, 조치 중 → 종결, 조치 결과 없이 종결 거부.

## 한계

- 불량 유형이 자유 입력이라 표기가 다르면 다른 유형으로 집계된다. 유형 목록을 정해 주면 선택 방식으로 바꿀 수 있다.
- 외주사가 제출한 Issue 접수가 이 목록에 자동으로 들어오지 않는다. 필요한 건은 직접 등록하고 접수 번호를 연결한다.
- 기간 필터와 월별 추이는 없다.
